# Domain Content Map — Testing, Auditing, and Compliance: Verifying Visualization Accessibility

Read this during Phase 3 (architecture) and Phase 4 (writing) of the module
development workflow. Verify all factual claims and numbers against the
authoritative sources before publishing (Phase 2 evidence base); flag
anything disputed rather than repeating it.

## Absorbed capabilities this module must produce
1. Operate the three-pillar verification strategy (automated-at-scale, expert-manual, disabled-user testing) with coverage-limits mapping and pyramid investment sequencing.
2. Build automated programs (axe-core CI integration with custom chart rules, accessibility-tree-and-focus-order assertions, live-region observation, false-positive governance, coverage metrics, regression gates).
3. Execute expert reviews (unplug-the-mouse keyboard protocols, cross-AT screen-reader sessions with announcement assessment, WCAG systematic audits with evidence collection, domain heuristics, reviewer calibration).
4. Run disabled-user programs (representative journey design, diverse ethical recruitment, moderated-unmoderated-comparative methods, severity-frequency-qualitative analysis, participation ethics with feedback closure).
5. Manage audit lifecycles (scoping-sampling, multi-pillar execution with reproducible documentation, layered reporting with prioritization matrices, retest verification, shift-left evolution).
6. Handle formal compliance (self-versus-third-party assessment, VPAT-ACR-statement production and maintenance, contractual-legal response, certification options, multi-jurisdiction architecture).
7. Instrument metrics (issue-density-finding-fix-reopen-coverage testing metrics, privacy-respecting field signals, quality gates, metric governance) while preventing scanner-only-checklist-ceiling-single-AT-static-lab-only-graveyard-fiction-theater anti-patterns.
