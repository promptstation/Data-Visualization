# Domain Content Map — Cognitive, Neurological, and Language Accessibility: Understandable Visualization

Read this during Phase 3 (architecture) and Phase 4 (writing) of the module
development workflow. Verify all factual claims and numbers against the
authoritative sources before publishing (Phase 2 evidence base); flag
anything disputed rather than repeating it.

## Absorbed capabilities this module must produce
1. Serve cognitive accessibility across the disability-spectrum-situational-load continuum by building plain-language systems (jargon-free chart text, terminology registries with glossaries, locale-clear number-date formats, structured error-feedback language).
2. Manage cognitive load through progressive disclosure with simplified defaults, visual complexity reduction under single-message composition, comparison-memory-attention supports (anchors, consistency, persistent labels, state visibility, salience hygiene, motion restraint), engineer predictability-tolerance (consistent behaviors without context-change surprises, error prevention-recovery, reversible exploration safety, user-controlled pacing, state-freshness transparency).
3. Apply neurodiversity-informed design (autism sensory-literal-predictability supports, ADHD chunking-focus balance, dyslexia typography-text-speech-multiformat provisions, anxiety calm-control-reassurance patterns, processing-difference multi-representation choice).
4. Build accessible explanation patterns (guided reading, insight-takeaway-context provision, learning support, feedback confirmation).
5. Validate through message-extraction comprehension testing, cognitive-disability user research with supported participation, readability-terminology-wayfinding assessment, heuristic review, and telemetry-informed iteration, and prevent jargon-wall-complexity-dump-surprise-memory-race-blame-sensory-monoculture-untested anti-patterns.
