# Domain Content Map — Text Alternatives, Data Descriptions, and Sonification: Non-Visual Data Access

Read this during Phase 3 (architecture) and Phase 4 (writing) of the module
development workflow. Verify all factual claims and numbers against the
authoritative sources before publishing (Phase 2 evidence base); flag
anything disputed rather than repeating it.

## Absorbed capabilities this module must produce
1. Architect text alternatives through the four-tier hierarchy (label-summary-detailed-data) selected by complexity-context, author descriptions under what-data-shows-not-how-to-read principles with quantitative precision, speech-friendly formatting, uncertainty honesty, and dynamic-data synchronization.
2. Build structured equivalents (toggleable data-table companions with AT-optimized navigation, download-API access, tree-network-spatial representation conventions).
3. Design sonification systems (pitch-timbre-spatialization mappings, earcon-interactive patterns, web-audio-library implementation, optional-enhancement integration, limits honesty), provide tactile-large-print-simplified multi-sensory variants under orchestrated representation suites with user choice, scale through template-and-AI generation with mandatory human verification and quality assurance.
4. Integrate via in-context-hidden-expandable-modal-linked delivery patterns under universal-design balance, prevent type-name-theater-mechanics-narration-enumeration-staleness-burial-uncontrolled-audio-unreviewed-AI-monoculture anti-patterns.
5. Validate through blind-user comprehension testing, AT efficiency measurement, sonification efficacy evaluation, cross-representation consistency, and portfolio coverage tracking.
