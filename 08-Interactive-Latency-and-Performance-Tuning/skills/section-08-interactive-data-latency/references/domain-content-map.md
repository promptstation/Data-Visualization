# Domain Content Map — Data Latency: Queries, Aggregation, Transfer, and the Computation Pipeline

Read this during Phase 3 (architecture) and Phase 4 (writing) of the module
development workflow. Verify all factual claims and numbers against the
authoritative sources before publishing (Phase 2 evidence base); flag
anything disputed rather than repeating it.

## Absorbed capabilities this module must produce
1. Engineer data latency across the request-network-parse-transform-aggregate-encode pipeline with scale-relationship analysis and full-stack budget ownership.
2. Optimize transfer through payload projection, compression, binary formats, request coalescing with preload hints, layered HTTP-IndexedDB-CDN caching with invalidation strategies, and streaming delivery, offload parsing via workers, streaming-incremental parsers, Arrow zero-copy consumption, and decode-during-download overlap.
3. Optimize computation through single-pass aggregations, hash-keyed group-bys, server precomputation pyramids, index-predicate-pushdown queries, sampling-sketch approximation with honesty disclosure, and memoized aggregation caches, collaborate on backend latency (endpoint characterization, visualization-shaped APIs, embedded data, push architectures, distributed tracing), architect client state-cache layers with SWR revalidation, derived-state memoization, optimistic patterns, and memory budgets, orchestrate progressive data delivery with priority-backpressure-partial-honesty discipline.
4. Measure through resource-timing decomposition, waterfall analysis, scale curves, field RUM, and budget verification, prevent over-fetch-waterfall-parse-monolith-recompute-stale-cache anti-patterns.
5. Synthesize end-to-end architectures by data-characteristic class.
