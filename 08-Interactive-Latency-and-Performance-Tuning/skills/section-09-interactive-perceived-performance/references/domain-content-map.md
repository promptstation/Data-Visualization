# Domain Content Map — Perceived Performance: Optimistic UI, Skeletons, and Progress Design

Read this during Phase 3 (architecture) and Phase 4 (writing) of the module
development workflow. Verify all factual claims and numbers against the
authoritative sources before publishing (Phase 2 evidence base); flag
anything disputed rather than repeating it.

## Absorbed capabilities this module must produce
1. Engineer perceived performance by operationalizing Maister wait-psychology principles (occupied, pre-process, uncertain, anxiety wait reductions) within honesty boundaries.
2. Build immediate-acknowledgment patterns (sub-100ms input states, acknowledgment-before-completion sequencing, layout-matched skeletons with shimmer-reduced-motion discipline, partial-content immediacy), architect optimistic UI (pending-state encoding, rollback-communication engineering, operation-scope decisions, stale-while-revalidate visuals, race-condition verification).
3. Design progress indication through the indicator taxonomy with psychophysics conventions (delay thresholds, smooth animation, honest estimation, localized states, cancellation-background-continuation for long operations), engage active waits (productive content, progressive feature availability, meaningful motion masking, hover-intent prefetching).
4. Build load experiences via critical-path prioritization, shell-first assembly, embedded-bootstrap-cache-warm data strategies with LCP-subjective correlation measurement.
5. Design error-slow-state communication (threshold escalation, retry recovery, partial-failure isolation, freshness honesty).
6. Validate through subjective-behavioral-objective correlation testing with accessibility of busy-live semantics, prevent blank-wait-spinner-forever-layout-jump-fake-progress-no-rollback over-animation-stale-as-fresh anti-patterns.
7. Integrate the perception stack as standard architecture with state-machine modeling and team standards.
