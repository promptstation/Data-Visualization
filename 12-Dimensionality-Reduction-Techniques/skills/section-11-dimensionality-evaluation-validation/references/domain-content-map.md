# Domain Content Map — Evaluation and Validation: Knowing Whether an Embedding Can Be Trusted

Read this during Phase 3 (architecture) and Phase 4 (writing) of the module
development workflow. Verify all factual claims and numbers against the
authoritative sources before publishing (Phase 2 evidence base); flag
anything disputed rather than repeating it.

## Absorbed capabilities this module must produce
1. Validate embeddings through evaluation frameworks (preservation-fidelity questions with fitness-for-purpose framing, evidence-type taxonomy, timing discipline, honesty principles with metric complementarity), deploy quantitative metrics (trustworthiness-continuity-recall neighbor families, Mantel-Shepard distance correlations with local-global separation, cluster-agreement and silhouette structure recovery in original space, density fidelity with artifact-detection statistics, metric-suite composition discipline).
2. Assess stability (multi-seed ensembles with Procrustes alignment, parameter sensitivity sweeps with interaction awareness, subsample-noise-outlier perturbation robustness, initialization-pipeline-version variation, reporting standards with unstable-structure flagging).
3. Run ground-truth validation (synthetic planted-structure benchmarks with difficulty ladders, semi-synthetic designs, domain marker-content-law reference checks, downstream task evaluation with caveats, benchmark hygiene), triangulate across methods (multi-method concordance with disagreement diagnosis, consensus and ensemble approaches, structured and adversarial expert review, evidence-pyramid integration with proportional rigor), cultivate continuous validation (revalidation triggers, knowledge accumulation, community evidence integration), and avoid validation skipping, single-metric reduction, stability neglect, benchmark-only trust, downstream conflation, agreement theater.
4. Review absence, and validation opacity failures.
