# Misreadings and Pitfalls: The Taxonomy of Embedding Lies — Professional Training

## Mission

the cluster proximity inference hazard where "these groups are related" claims rest on nothing but layout position; the remediation discipline requiring original-space distance verification before any between-group similarity claim); the cluster size and density fallacies (the area-equals-size misreading where embedding cluster extents are assumed proportional to population counts, contradicted by the critique literature; the density-equals-concentration misreading where point density in layouts is assumed to reflect input density, the finding that motivated density-preserving extensions; the within-cluster structure overreading that treats sub-patterns inside clusters as meaningful geometry without stability verification); the global structure fallacies (the macro arrangement interpretation error reading overall layout shape as data structure when global preservation is partial at best; the gradient direction assumption reading left-to-right or center-to-edge progress without original-data trajectory verification; the initialization global illusion where arrangement inherited from PCA initialization is mistaken for method-preserved structure); the axis and coordinate fallacies (the axis meaning invention assigning interpretations to embedding dimensions that have no intrinsic semantics, unlike PCA's loadings-based axes; the coordinate value comparison error treating layout coordinates as measurable quantities for arithmetic or ranking; the relational fallacy family — comparison and communication misreadings: the cross-embedding comparison errors (the unaligned layout comparison fallacy juxtaposing embeddings with different rotations, scales, and parameters as if directly comparable; ## Writing Standards

Throughout the material, prioritize language that is:

* Precise without becoming jargon-heavy
* Practical without discarding rigor
* Honest about limitations and contested findings without being defeatist
* Concrete — anchored in real cases, real artifacts, and verifiable numbers
* Progressive from fundamentals to expert judgment

Where a recommendation depends on context, explain the trade-off rather than presenting an absolute rule.

## Anti-Patterns

Avoid: Cluster-geometry overreading — measuring distances between t-SNE or UMAP clusters, comparing cluster sizes and densities, and reporting embedding-space quantities the algorithms never promised to preserve; Parameter roulette — running defaults once, or worse, sweeping perplexity and n_neighbors until the picture matches the hoped-for story, with no sensitivity documentation; Single-run trust — treating one stochastic embedding as ground truth when seed variation produces materially different layouts, skipping stability assessment entirely; Method monoculture — reaching for t-SNE or UMAP for every problem, ignoring when PCA, MDS, or hierarchical structure better serves the analytic question; Preprocessing amnesia — embedding raw, unscaled, outlier-ridden, or badly normalized data and blaming the algorithm for garbage layouts the inputs guaranteed; exercises without evaluation criteria; modules that stop at inspiration without a single decision the learner can now make better; and any content that overstates certainty beyond what the evidence supports.

## Decision Heuristic

When allocating depth under time or length limits, ask:

1. Where will this audience actually stall in practice?
2. Which unit protects the most value if taught well?
3. Can the learner run the framework tomorrow without me?
4. Is every example doing work a plain sentence could not?
5. What would a skeptical domain expert say about this material?

If two topics compete for space, keep the one that changes a decision.
