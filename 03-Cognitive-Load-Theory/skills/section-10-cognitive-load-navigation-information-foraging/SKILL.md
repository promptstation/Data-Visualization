# Navigation Load and Information Foraging: Finding Without Fatigue — Professional Training

## Mission

Produce professional-grade learning modules and training materials on **navigation Load and Information Foraging: Finding Without Fatigue** within The science of working-memory limits applied to information design — managing intrinsic, extraneous, and germane load so complex dashboards inform users without overwhelming or fatiguing them.

Subject scope: Covers the wayfinding-cost dimension: information-foraging theory — the navigation model: the Pirolli-Card framework (users as foragers following information scent — the cue-trails suggesting value ahead, with the cost-value economics: navigation paths chosen by expected-information-gain per interaction-cost) as the theory of dashboard and analytics-system wayfinding, making navigation design a scent-engineering discipline; the scent-craft — the cue design: the documented scent strengtheners (the descriptive-over-generic labels — 'Q3 Revenue Exceptions' over 'Details', the preview-snippets and thumbnails signaling content, the consistent-terminology matching the user's task vocabulary, the breadcrumb-trail state visibility) and the scent-killers (the mystery-icons, the jargon-mismatch labels, the dead-end navigations without return-scent) as the wayfinding-cue toolkit; the orientation-load management — the where-am-I problem: the documented disorientation costs (the lost-in-hyperspace findings from hypertext research transferred to dashboard hierarchies — the re-orientation working-memory tax after navigation: rebuilding the context model consumes the capacity saved by the destination), with the orientation-support patterns (the persistent-context anchors — the always-visible location indicators, the transition-continuity animations preserving the spatial mental model — the course-2 motion-continuity applied to navigation, the overview-map patterns — the miniaturized global view with position highlight); the navigation-structure load — the architecture effects: the breadth-depth trade-off quantified (the documented menu-structure findings: the optimal breadth at each level minimizing total navigation cost — the wide-shallow advantage for load with the scan-cost ceiling), the structure-consistency requirement (the same navigation grammar across the system — the automated wayfinding schema), and the path-frequency alignment (the common-task paths as one-interaction routes, the rare paths tolerating depth — the frequency-weighted architecture) as the structure-load engineering; the search-and-filter load — the query interface: the search-as-navigation pattern (the direct-access alternative to hierarchy traversal with the vocabulary-matching requirement — the synonym and typo tolerance as scent), the filter-state visibility (the active-filter display preventing the forgotten-filter confusion — the state-amnesia load), and the query-result-orientation (the result-to-source context links — the finding-within-context patterns) as the query-load management; the cross-tool navigation — the ecosystem wayfinding: the multi-dashboard and system navigation (the portal-hierarchy scent design, the cross-system deep-links preserving context, the tab-and-window management load — the browser-level orientation costs) with the destination-consistency standard (the same metric looking and behaving the same across tools — the cross-system schema coherence) as the ecosystem-load discipline; the interruption-and-resumption load — the return navigation: the documented resumption costs (the interruption-recovery research: re-finding position and state after diversion — the attention-residue effect), with the resumption-support patterns (the session-state persistence, the return-to-last-position defaults, the change-since-last-visit summaries — the streaming-course-13 connection, the bookmark and annotation personalization) as the interrupted-user load relief; the mobile-and-small-screen navigation — the constrained wayfinding: the viewport-limited orientation (the scroll-position-as-navigation problem, the collapsed-hierarchy patterns — the drawer and bottom-sheet navigation with the context-loss trade-offs, the thumb-reach interaction-cost geography) as the small-screen load adaptation; the foraging-measurement practice — the navigation evidence: the path-analysis telemetry (the actual navigation sequences versus designed paths — the revealed-foraging data, the dead-end and backtrack rates as the scent-failure metrics), the task-time decomposition (the navigation-fraction of total task time — the wayfinding-cost quantification), and the disorientation-event tracking (the rapid-back-navigation and search-after-navigation patterns as the lost-user signals) as the foraging-evidence system; the navigation anti-patterns — the failure catalog: the scent-free-iconography (the symbol-only navigation requiring learned-decoder rings — the expert-only wayfinding), the context-destroying navigation (the full-page transitions losing orientation — the teleportation failure), the filter-amnesia (invisible active filters corrupting comprehension — the hidden-state load), and the hierarchy-first-default (forcing navigation for the most common task — the zero-interaction-value violation from section 9) as the wayfinding-hygiene rules; and the foraging deliverable — the scent-rich, orientation-preserving, resumption-supporting navigation-load architecture.

Write as an experienced practitioner, not as a summarizer of popular content. Every framework taught must be something a real team or professional could run: procedures they can execute, criteria they can judge with, and artifacts they can hand to a colleague. Throughout the material, prioritize language that is:

## Anti-Patterns

Avoid: Treating load as only-about-quantity — element interactivity, not element count, drives intrinsic load: four interacting series can cost more than forty parallel ones; Optimizing extraneous load to zero while ignoring germane load — frictionless displays that teach nothing, leaving users permanently dependent on the designer's pre-chewing; Expertise-reversal blindness — scaffolding that helps novices (guides, annotations, step-by-step layering) becoming redundant load for experts, one design serving neither; Density panic — stripping legitimate information to reduce felt complexity, when the real fix is structure: chunking, alignment, and progressive disclosure carrying density at low load; Measuring load by asking designers — self-report from the display's authors is worthless; load evidence requires naive users, workload scales, and performance triangulation; exercises without evaluation criteria; modules that stop at inspiration without a single decision the learner can now make better; and any content that overstates certainty beyond what the evidence supports.

## Decision Heuristic

When allocating depth under time or length limits, ask:

1. Where will this audience actually stall in practice?
2. Which unit protects the most value if taught well?
3. Can the learner run the framework tomorrow without me?
4. Is every example doing work a plain sentence could not?
5. What would a skeptical domain expert say about this material?

If two topics compete for space, keep the one that changes a decision.
