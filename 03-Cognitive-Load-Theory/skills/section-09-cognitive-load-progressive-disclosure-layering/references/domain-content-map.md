# Domain Content Map — Progressive Disclosure and Layering: Sequencing Load Over Time

Read this during Phase 3 (architecture) and Phase 4 (writing) of the module
development workflow. Verify all factual claims and numbers against the
authoritative sources before publishing (Phase 2 evidence base); flag
anything disputed rather than repeating it.

## Absorbed capabilities this module must produce
1. Architect progressive disclosure across four timescales (overview-detail drills, hover tooltips, expandable sections, staged onboarding) with working-set containment per stage, account disclosure costs (interaction, orientation, discoverability, false-completeness taxes) enforcing critical-information-never-deferred rules, engineer layer coherence through context preservation, transition continuity, and reliable return paths.
2. Select defaults via task-frequency and role-state logic meeting zero-interaction-value standards, govern depth within three-level ceilings with breadth-depth trade-offs and escape hatches.
3. Validate through path analysis, discovery testing, and abandonment mapping preventing burial, maze, hover-dependency, and theater failures.

## Unit 1 — Unit 1

**Scope:** Covers the temporal load-management strategy: progressive disclosure defined — the sequencing principle: presenting only the necessary information at each stage, deferring advanced or secondary content until requested (the documented interaction-design principle with its load mechanism: the working-set containment per stage — each view holding its chunk-count under budget, the decision-tree narrowing — each disclosure step reducing the remaining search space); the disclosure-architecture patterns — the layering toolkit: the overview-first sequences (the summary-to-detail drill paths — the Shneiderman mantra as load-sequencing, the zoom-and-filter progressions), the hover-and-tooltip layer (the on-demand detail without layout cost — the transient-disclosure pattern with the discoverability problem: invisible affordances never requested — the tooltip-discovery design), the expandable-section mechanics (the accordion and progressive-panel patterns — the user-paced depth control per the segmenting principle), and the staged-onboarding sequences (the first-run guided exposure, the feature-progressive revelation across sessions — the long-horizon disclosure) as the four-timescale layering system; the disclosure-cost accounting — the interaction economics: the hidden costs of deferral (the interaction-load per disclosure — the click, hover, and wait costs charging executive load per section 2, the orientation-cost — the context-switching between disclosure levels, the discoverability-tax — the learning cost of the disclosure system itself, the false-completeness risk — the viewer missing deferred critical information) requiring the disclosure-worth analysis (what is deferred must be genuinely optional for the majority task — the critical-information-never-deferred rule); the layer-coherence requirement — the continuity discipline: the cross-layer context preservation (the deferred-detail views maintaining the parent context — the breadcrumb and persistent-selection patterns, the detail-in-context alternatives: the in-place expansion over navigation-away disclosure — the orientation-load comparison), the visual-continuity of transitions (the animated layer-connections preserving object identity — the course-1 and 2 transition principles applied to disclosure), and the return-path reliability (the back-navigation and state-restoration — the lost-in-hyperspace prevention from the navigation-load literature) as the coherence engineering; the default-layer selection — the entry-point design: the initial-view decision framework (the task-frequency-weighted default — the most common task's working set as the landing composition, the role-based defaults — the executive versus analyst entry views, the state-aware defaults — the exception-present views versus calm-state views: the adaptive-entry logic) with the default-quality test (does the unmodified first view answer the most common question without interaction — the zero-interaction-value standard); the disclosure-depth governance — the layer-count discipline: the depth-limit findings (the documented navigation-depth degradation — the three-level practical ceiling before disorientation, the breadth-versus-depth trade-off: wider-shallower structures outperforming narrow-deeper for load), the level-consistency requirement (the same disclosure-depth semantics across the dashboard — the convention-automation), and the escape-hatch design (the reset-overview and search-shortcuts bypassing the hierarchy — the load-recovery paths) as the depth management; the progressive-rendering integration — the technical layer: the disclosure-as-performance pattern (the deferred data-loading and lazy-rendering — the course-8 latency connection: perceived-responsiveness as load factor, the skeleton-and-placeholder conventions signaling incoming content — the wait-load reduction), the computation-staging (the expensive aggregations deferred until disclosure — the interaction-latency budgeting), and the pre-fetch intelligence (the likely-next-layer anticipation — the hover-preload patterns balancing responsiveness against waste) as the implementation craft; the disclosure anti-patterns — the failure catalog: the burying-critical-data error (the decision-essential information behind undisclosed layers — the false-completeness failure realized), the disclosure-maze (the nested popovers and modal stacks losing context — the orientation-collapse), the hover-dependency (the touch-device and accessibility failures of hover-only disclosure — the pointer-privileged information trap, the course-9 integration), and the disclosure-theater (the layered presentation of trivially-small information — the complexity-costume: disclosure systems adding interaction load to reduce nothing) as the hygiene rules; the disclosure-measurement practice — the validation layer: the task-completion-path analysis (the interaction-count and time-to-answer per task across disclosure variants, the discovery-rate testing — do users find the deferred features, the abandonment-point mapping — where disclosure sequences lose users) with the default-view efficacy test (the zero-interaction question-answering rate) as the disclosure-evidence system; the layering-design workflow — the integration practice: the information-tiering exercise (the content inventory sorted by task-criticality and frequency into the always-visible, one-interaction, and deep layers), the layer-boundary drawing (the chunk-coherent grouping per level — the disclosure cuts at semantic joints not arbitrary sizes), and the transition-design specification (the continuity, orientation, and return patterns per boundary) as the systematic layering method; and the progressive-disclosure deliverable — the sequenced, coherent, measured multi-layer load architecture.
