# Dashboard Complexity Management: Density, Structure, and Glanceability — Professional Training

## Mission

Produce professional-grade learning modules and training materials on **dashboard Complexity Management: Density, Structure, and Glanceability** within The science of working-memory limits applied to information design — managing intrinsic, extraneous, and germane load so complex dashboards inform users without overwhelming or fatiguing them.

Subject scope: Applies the load framework to the dashboard craft: the complexity paradox — the density defense: the documented reality that information density itself is not load (the structured-density findings: well-chunked dense displays outperforming sparse unstructured ones — theFew doctrine that dashboards should be dense but glanceable), distinguishing quantity-complexity (element count — manageable through hierarchy) from interactivity-complexity (relationship count — the true load driver per section 1's element-interactivity principle) as the complexity-type diagnosis; the dashboard-taxonomy by load profile — the display classes: the monitoring dashboard (the exception-detection load profile — the glanceable-state-at-a-glance design, the preattentive-course-2 dependence, the low-interactivity high-frequency reading), the analysis dashboard (the comparison-and-integration profile — the interactive exploration with working-set management), the reporting dashboard (the narrative-comprehension profile — the sequenced reading path with schema-support annotations), and the operational control view (the action-decision profile — the status-plus-control integration) each requiring distinct load architectures; the hierarchy-and-layering craft — the structural load management: the overview-detail hierarchy (the summary-tile to detail-panel progression — the load-staged information architecture, the Shneiderman-mantra connection to course 7), the visual-hierarchy-as-load-priority (the salience-tier mapping to decision-priority from course 2 section 10, the reading-path choreography removing navigation decisions), and the progressive-density zoning (the dense-monitoring regions adjacent to spacious-analysis regions — the mixed-density composition with zone-boundary clarity) as the layered complexity architecture; the panel-design load standards — the component craft: the single-message-panel principle (the one-chart-one-question discipline — the panel working-set containment), the panel-header schema-priming (the interrogative and takeaway titles activating the reading frame — the section-5 pre-training applied at panel scale), the consistent-encoding convention (the same-color-same-meaning and same-scale-family rules removing per-panel re-learning — the convention-automation load relief), and the chrome-minimalism standard (the axis, gridline, and border reduction to the comprehension minimum — the coherence principle at panel level) as the component load grammar; the comparison-support systems — the interactivity reduction: the embedded-reference architecture (the target lines, prior-period ghosts, benchmark bands — the section-7 externalization at dashboard scale), the computed-insight panels (the exception lists, the change-summaries, the automated callouts — the pre-digested comparisons reducing the viewer's integration load with the pre-chewing-dependency caution from section 3), and the linked-view mechanics (the cross-filter and brush-highlight propagation — the cross-panel binding externalized through interaction rather than memory) as the relationship-load toolkit; ## Writing Standards

Throughout the material, prioritize language that is:

* Precise without becoming jargon-heavy
* Practical without discarding rigor
* Honest about limitations and contested findings without being defeatist

Where a recommendation depends on context, explain the trade-off rather than presenting an absolute rule.

## Anti-Patterns

Avoid: Treating load as only-about-quantity — element interactivity, not element count, drives intrinsic load: four interacting series can cost more than forty parallel ones; Optimizing extraneous load to zero while ignoring germane load — frictionless displays that teach nothing, leaving users permanently dependent on the designer's pre-chewing; Expertise-reversal blindness — scaffolding that helps novices (guides, annotations, step-by-step layering) becoming redundant load for experts, one design serving neither; Density panic — stripping legitimate information to reduce felt complexity, when the real fix is structure: chunking, alignment, and progressive disclosure carrying density at low load; Measuring load by asking designers — self-report from the display's authors is worthless; load evidence requires naive users, workload scales, and performance triangulation; exercises without evaluation criteria; modules that stop at inspiration without a single decision the learner can now make better; and any content that overstates certainty beyond what the evidence supports.

## Decision Heuristic

When allocating depth under time or length limits, ask:

1. Where will this audience actually stall in practice?
2. Which unit protects the most value if taught well?
3. Can the learner run the framework tomorrow without me?
4. Is every example doing work a plain sentence could not?
5. What would a skeptical domain expert say about this material?

If two topics compete for space, keep the one that changes a decision.

The module must function simultaneously as a learning resource, a practical reference, and a working methodology.
