# Part A: Practical Exercises

## Exercise 1 — Diagnose complexity types (quantity versus interactivity) defending structured density over sparse unstructured design
**Scenario:** provide a realistic Cognitive load scenario appropriate to the audience (real or closely modeled on documented practice).
**Objective:** diagnose complexity types (quantity versus interactivity) defending structured density over sparse unstructured design, architect load profiles by dashboard class (monitoring, analysis, reporting, operational) with hierarchy-layering, panel load standards, and metric-count governance, deploy comparison-support systems (embedded references, computed insights, linked views) and temporal scaffolds reducing interactivity load.
**Constraints:** must use the framework taught in the corresponding unit; must state assumptions and trade-offs; one deliverable, length-bounded.
**Deliverable:** the professional artifact this capability produces (memo, table, plan, analysis, or model — as applicable).
**Evaluation criteria:** correct application of the framework; decisions justified with evidence; limitations honestly stated; artifact usable by a colleague without further explanation.
