# Domain Content Map — The Three Load Types: Intrinsic, Extraneous, Germane

Read this during Phase 3 (architecture) and Phase 4 (writing) of the module
development workflow. Verify all factual claims and numbers against the
authoritative sources before publishing (Phase 2 evidence base); flag
anything disputed rather than repeating it.

## Absorbed capabilities this module must produce
1. Classify display load into intrinsic (element-interactivity of content and task), extraneous (presentation waste), and germane (schema-building investment) types with source identification.
2. Operate the load-budget equation (minimize extraneous, free capacity, fund germane and performance) with interaction-dynamics awareness including overload cliffs and expertise shifts.
3. Measure each type through baselines, variant comparisons, and transfer tests, prevent load-type anti-patterns (misdiagnosis, germane elimination, intrinsic avoidance, load shifting) through load-source audits.
4. Manage intrinsic load temporally through isolation sequences, worked examples, and fading scaffolds with expertise-conditional personalization.

## Unit 1 — Unit 1

**Scope:** Covers the framework's accounting core: intrinsic load — the inherent complexity: the element-interactivity of the content itself (the multi-variable comparison, the trend-exception correlation, the cross-panel integration — the interacting elements the task requires holding simultaneously), its sources in data (the dimensionality, the relationship complexity, the domain-knowledge prerequisites) and task (the comparison depth, the precision requirements), and its management impossibility-plus-alternatives (intrinsic load cannot be deleted without changing the task — it can be sequenced: the part-task progressions, the completed-example scaffolds, the isolation-of-elements-then-integration pedagogy applied to dashboard onboarding and layering); extraneous load — the presentation waste: the processing imposed by how information is delivered rather than what it conveys (the documented sources: split-attention layouts, redundant duplication, unclear encodings requiring conscious decoding, decorative elements demanding suppression, poor navigation requiring re-orientation) as the designer's primary responsibility — the load that buys the viewer nothing and the primary target of elimination; germane load — the productive effort: the capacity spent building and automating schemas (the sense-making work: relating new data to known patterns, constructing the mental model of the system being monitored, learning the dashboard's conventions), its status in the modern framework (the germane-as-schema-construction view — effort that is intrinsic load directed at learning), and its design treatment (protection and cultivation — the scaffolds, comparisons, and annotations that make productive thinking easier rather than eliminating all effort); the load-budget equation — the accounting practice: total load as intrinsic plus extraneous constrained by capacity, with germane load as the intrinsic-plus investment (the budget allocation: minimize extraneous → free capacity → the freed capacity funds germane processing and task performance — the load-management sequence) making every design decision a budget reallocation; the interaction dynamics — the load couplings: the documented interactions (high extraneous load crowding out germane processing — the learning-degradation under bad design; high intrinsic load amplified by extraneous additions — the overload cliff where total exceeds capacity producing the comprehension collapse; the expertise-mediated shifts — what is germane for novices becomes automated and what is extraneous for experts may be germane scaffolding for novices — the expertise-reversal preview) as the dynamic accounting; measuring the three types — the assessment mapping: the instrumentation per load type (the intrinsic: task-difficulty baselines and element-interactivity counts; the extraneous: the design-variant comparisons — same task and data, different presentation, with performance and workload deltas; the germane: the learning and transfer measures — the schema-acquisition tests, the post-exposure performance improvement) as the three-type evidence system; the dashboard-application frame — the BI translation: intrinsic load sources in dashboards (the KPI interdependencies, the time-series comparison demands, the exception-judgment complexity), extraneous load sources (the chrome, inconsistent encodings, separated labels, gratuitous animation), germane load value (the analyst's system-model building, the executive's metric-relationship learning) with the audit practice (the load-source inventory per display element — what load does this add, of which type, earning what?) as the applied accounting; the load-type anti-patterns — the failure catalog: the extraneous-as-intrinsic misdiagnosis (blaming the data's complexity when the presentation causes the strain — the fixable-problem denial), the germane-elimination error (over-simplifying until no understanding is built — the pre-chewed-dashboard dependency trap from the pitfalls), the intrinsic-avoidance (refusing the necessary complexity — the dumbing-down failure where the task genuinely requires multi-element integration), and the load-shifting illusion (moving load between views without reducing it — the progressive-disclosure-without-coherence failure previewed for section 9); the sequencing-and-scaffolding craft — the intrinsic management: the element-isolation sequences (the single-series-first then comparison layering), the worked-example progression (the annotated exemplar analyses teaching the reading patterns), and the completion-fading scaffolds (the gradually removed supports — the training-wheel cadence) as the intrinsic-load temporal management toolkit; the load-personalization horizon — the adaptive view: the expertise-conditional load profiles (the same display carrying different load compositions for different viewers — the section-14 adaptation preview) with the practical responses (the role-based views, the toggleable scaffolds, the progressive complexity) as the multi-audience load strategy; and the three-load deliverable — the accounting-fluent load classification, budgeting, and measurement practice.
