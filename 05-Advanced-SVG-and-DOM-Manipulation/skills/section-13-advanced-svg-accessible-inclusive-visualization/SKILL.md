# Accessible SVG and Inclusive Visualization — Professional Training

## Mission

Produce professional-grade learning modules and training materials on **accessible SVG and Inclusive Visualization** within Absolute mastery of D3.js — the gold standard for custom web-based data visualization — including advanced SVG craft, the data-join mental model, layouts and transitions, and integration with React, Vue, and Svelte.

Subject scope: Covers the inclusion obligation and craft: the accessibility-problem statement — the exclusion reality: the default-inaccessibility of data graphics (the SVG-as-picture problem — screen readers announcing nothing or nonsense for unannotated charts, the color-only encodings excluding CVD viewers, the interaction-only information excluding keyboard users, the motion-triggering vestibular disorders) with the standards-and-law context (the WCAG success criteria applicable to non-text content and complex graphics, the EN-301-549 and ADA-EAA regulatory drivers) establishing accessibility as professional obligation not enhancement; the SVG-semantics foundation — the document accessibility: the role-and-title-description architecture (the role="img" with title-and-desc elements and aria-labelledby-describedby wiring — the basic-chart announcement pattern, the role="graphics-document" and WAI-ARIA Graphics Module roles — the graphics-symbol and graphics-object semantics for structured exploration), the focusability mechanics (the tabindex enabling keyboard traversal of mark groups, the focus-indicator visibility requirements), and the reading-order engineering (the DOM-order-as-reading-order discipline — the logical mark sequencing for sequential announcement) as the semantic foundation; the text-alternative strategy — the description craft: the alt-text-equivalent decisions (the concise-summary versus detailed-description spectrum by chart complexity and context, the W3C diagram-summary guidance — the description answering what-the-data-shows not what-the-chart-looks-like), the longdesc-and-linked-description patterns (the extended textual analysis accompanying complex graphics, the details-summary and modal alternatives), and the auto-generated-description cautions (the template-summary limitations — the data-driven 'the chart shows X' text versus analyst insight, the human-authored-summary requirement for meaning) as the description discipline; the data-table-and-structure fallback — the equivalent-access layer: the tabular-data companion patterns (the visually-hidden or togglable data tables mirroring chart content — the sortable-filterable table advantages for exploration, the table-caption-and-header semantics), the data-download provisions (the CSV-and-API access as the ultimate fallback), and the synchronization discipline (the table-chart data consistency through shared-source rendering — the single-data-source component architecture) as the equivalent-access architecture; the color-and-encoding accessibility — the perceptual inclusion: the contrast-requirement application (the WCAG contrast ratios for text, graphical objects, and UI components — the 3:1 non-text contrast criterion for chart elements), the CVD-inclusive palettes (the deuteranopia-protanopia-safe schemes — the Okabe-Ito and CVD-optimized palettes, the simulation-verification workflow from the perceptual disciplines), the redundant-encoding mandate (the direct-labeling over legend-dependence, the pattern-and-shape companions to color, the value-annotation availability) and the dark-mode-and-print parity as the encoding inclusion; ## Writing Standards

Throughout the material, prioritize language that is:

* Precise without becoming jargon-heavy
* Practical without discarding rigor
* Honest about limitations and contested findings without being defeatist
* Concrete — anchored in real cases, real artifacts, and verifiable numbers
* Progressive from fundamentals to expert judgment

Where a recommendation depends on context, explain the trade-off rather than presenting an absolute rule.

## Anti-Patterns

Avoid: Fighting the data join — imperative append-and-update code ignoring enter-update-exit semantics, producing duplicated, orphaned, or stale elements as data changes; Framework double-ownership — letting both React/Vue/Svelte and D3 mutate the same DOM subtree, producing render conflicts, leaked listeners, and irreproducible state bugs; SVG scale blindness — pushing tens of thousands of nodes into the DOM where style recalculation and layout costs collapse frame rates, ignoring the documented element-count ceiling; Transition choreography chaos — animating everything with uncoordinated durations so comparisons become impossible and motion carries no object-continuity information; Inaccessible-by-default graphics — SVG shipped without titles, descriptions, focusable alternatives, or data-table fallbacks, excluding screen-reader and keyboard users entirely; exercises without evaluation criteria; modules that stop at inspiration without a single decision the learner can now make better; and any content that overstates certainty beyond what the evidence supports.

## Decision Heuristic

When allocating depth under time or length limits, ask:

1. Where will this audience actually stall in practice?
2. Which unit protects the most value if taught well?
3. Can the learner run the framework tomorrow without me?
4. Is every example doing work a plain sentence could not?
5. What would a skeptical domain expert say about this material?

If two topics compete for space, keep the one that changes a decision.
