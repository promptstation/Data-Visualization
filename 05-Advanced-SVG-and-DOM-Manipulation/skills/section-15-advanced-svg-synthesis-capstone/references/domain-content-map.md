# Domain Content Map — Synthesis and Capstone: The Custom Visualization System

Read this during Phase 3 (architecture) and Phase 4 (writing) of the module
development workflow. Verify all factual claims and numbers against the
authoritative sources before publishing (Phase 2 evidence base); flag
anything disputed rather than repeating it.

## Absorbed capabilities this module must produce
1. Execute the complete custom-visualization arc from requirement and tier selection through architecture, implementation, inclusion engineering, performance hardening, quality systems, and delivery, demonstrate four-pillar mastery (architectural judgment, mechanism fluency, production discipline, escape-hatch capability) over the consolidated SVG-D3-ecosystem-framework-performance-accessibility-component knowledge.
2. Integrate perception, load, graphics, spatial, IA, latency, math, EDA, narrative, and semiographic disciplines into visualization systems, prevent canonical failures (join-fighting, double-ownership, scale-blindness, transition chaos, inaccessible defaults) through documented systems, and uphold honest-encoding, inclusion-floor, performance-equity, and perceptual-respect ethics climbing toward visualization-systems leadership.

## Unit 1 — Unit 1

**Scope:** Prepares expert integration: the consolidated capability map — the SVG medium mastery (document structure, coordinates-transforms, styling, advanced filters-masks-patterns with cost governance), the D3 core (selections and the data-join mental model, scales-axes-encodings, shapes-layouts-geometries, transitions-interpolation, the full interaction system), the ecosystem fluency (modular D3, Observable Plot, community libraries, TypeScript, build integration), the framework architectures (React-Vue-Svelte ownership patterns, state coordination, SSR-hydration), the performance engineering (SVG ceilings, optimization ladders, canvas-WebGL hybrids, progressive rendering), the accessibility system (semantics, equivalents, keyboard-motion inclusion, testing), and the component-architecture practice (APIs, theming, QA, versioning, governance) as one custom-visualization discipline; the capstone workflow — the master arc: requirement analysis (the data characteristics, interaction profile, audience and accessibility needs, scale and performance budgets, framework context defining the architecture class), technology-tier selection (the Plot-versus-D3-versus-hybrid-versus-GPU decision through the escalation frameworks with simplest-sufficient discipline), architecture design (the component decomposition, the ownership-boundary map for framework integration, the data-flow and state architecture, the theming and token system), implementation (the join-driven or declarative mark rendering, the scale-encoding system, the interaction layer with linked views, the transition choreography with motion gating), inclusion engineering (the semantics, equivalents, keyboard parity, contrast and CVD verification), performance hardening (the element-budget compliance, the optimization-ladder application, the progressive and hybrid strategies as scale demands), quality systems (the unit-visual-interaction-a11y testing, the documentation and versioning), and delivery (the component-library packaging, the design-system integration, the performance-and-usage monitoring) as the complete professional cycle; the mastery thesis restated — the source's absolute-mastery standard: mastery demonstrated not by module-memorization but by architectural judgment (the right tier and pattern per context), mechanism fluency (the join, scale, interpolation, and event internals enabling any custom behavior), production discipline (the accessibility, performance, testing, and versioning systems), and escape-hatch capability (the descent to raw SVG, canvas, or WebGL when the problem demands — the graphics-APIs course integration) as the four-pillar mastery model; cross-course integration — the curriculum position: Gestalt and preattentive science (courses 1-2) governing the mark, grouping, and salience decisions the components implement, cognitive load (course 3) bounding the complexity and disclosure architecture, the graphics APIs (course 4) as the escalation partner for scale beyond SVG ceilings, spatial-3D visualization (course 6) consuming the geo and 3D-adjacent capability, information architecture (course 7) shaping the multi-view and navigation structures, latency engineering (course 8) setting the interaction-responsiveness budgets, accessibility (course 9) as the inclusion floor this course implements in SVG specifics, linear algebra (course 10) as the transform-and-projection mathematics, EDA (course 11) supplying the shaped data contracts, dimensionality reduction (course 12) as the embedding-rendering data source, scrollytelling (course 13) as the narrative-application of the transition and scroll craft, semiographics (course 14) as the custom-mark-design partner, and executive communication (course 15) as the high-stakes delivery context; case synthesis — the worked systems (the bespoke multi-view analytics dashboard in React with hybrid canvas-SVG rendering and full keyboard parity, the editorial scrollytelling feature with choreographed D3 transitions and reduced-motion variants, the enterprise chart design-system with headless core and three framework wrappers, the real-time monitoring display escalating from SVG to deck.gl under data growth) decomposed through the capstone workflow; failure post-mortems — the canonical errors (join-fighting without the mental model, framework double-ownership corruption, SVG scale-blindness, transition chaos, inaccessible-by-default shipping, recipe-copying without primitive understanding, premature-abstraction component design) with the prevention systems from sections 1-14; the maturity model — stage one (SVG and join fluency — the primitives mastered), stage two (complete custom charts — the scale-shape-layout-transition-interaction integration), stage three (framework-integrated component systems — the production architecture with accessibility and performance discipline), stage four (visualization-systems leadership — the design-system governance, headless architecture, and cross-medium escalation judgment) as the capability roadmap; the craft-ethics position — the professional standard: the honest-encoding obligation (the interpolation and aggregation transparency, the scale-integrity discipline — the truncated-axis and proportional-area honesty), the inclusion-floor commitment (the accessibility as architecture not retrofit), the performance-equity awareness (the low-device functional experience), and the perceptual-respect principle (the load-and-salience science serving comprehension over decoration) as the visualization-craft ethics; and the capstone — a complete custom visualization system: select a real data and audience context, run the requirement and tier-selection analysis, design and implement the system (components, encodings, interactions, transitions) in a modern framework with explicit ownership architecture, engineer the inclusion layer (semantics, equivalents, keyboard, CVD-contrast), harden performance within budgets using the optimization ladder and hybrid strategies as needed, build the QA-documentation-versioning package, and deliver the system with architecture-decision records and perceptual-ethics compliance evidence.

## Unit 2 — Capstone integration

**Purpose:** integrate every capability above on one realistic problem end to end.

**Structure:** the learner takes a single problem in D3 and SVG through each unit's framework in sequence, producing a coherent deliverable that mirrors real professional documentation. Evaluation criteria: internal consistency across artifacts, evidence discipline, honest trade-off statements, and demonstrable use of each unit's framework.
