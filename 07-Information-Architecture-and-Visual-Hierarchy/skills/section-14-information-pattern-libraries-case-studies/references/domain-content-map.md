# Domain Content Map — Pattern Libraries and Case Studies: Structural Solutions in Practice

Read this during Phase 3 (architecture) and Phase 4 (writing) of the module
development workflow. Verify all factual claims and numbers against the
authoritative sources before publishing (Phase 2 evidence base); flag
anything disputed rather than repeating it.

## Absorbed capabilities this module must produce
1. Build and apply structural pattern libraries through the context-problem-solution-consequences documentation format with task-genre organization and adaptation-not-copying discipline, deploy entry patterns (landing dashboards, overview visualizations.
2. Search-alert-schedule entries), exploration patterns (workbenches, drill-down-across flows with state serialization, comparison workflows, discovery support), monitoring patterns (status walls, alert-context flows, freshness indication, escalation-action), narrative patterns (scrollytelling, reports, annotated explainers, share-publish), and governance patterns (metric catalogs, quality dashboards, permissions, feedback).
3. Analyze composite full-product cases end-to-end through journey mapping.
4. Diagnose anti-pattern cases (everything-dashboard, maze, filter-swamp, context-free-drill) via symptom-root-cause-repair anatomy, track AI-conversational-collaborative-headless structural trends anchored to enduring principles, and practice structured teardown analysis building personal pattern portfolios with critical gallery consumption.
