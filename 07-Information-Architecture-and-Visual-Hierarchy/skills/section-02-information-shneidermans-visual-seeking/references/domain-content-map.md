# Domain Content Map — Shneiderman's Visual Information-Seeking Mantra and the Analytic Task Framework

Read this during Phase 3 (architecture) and Phase 4 (writing) of the module
development workflow. Verify all factual claims and numbers against the
authoritative sources before publishing (Phase 2 evidence base); flag
anything disputed rather than repeating it.

## Absorbed capabilities this module must produce
1. Apply Shneiderman's mantra (overview-first, zoom-and-filter, details-on-demand) as a three-beat navigation rhythm with perceptual grounding in cognitive maps, working-memory externalization, and orientation-cost reduction.
2. Map the seven-plus-one information-seeking tasks and eight golden tasks to interface capabilities with task-coverage audits.
3. Design each beat through its pattern families (summary overviews with glanceability discipline, semantic zoom with faceted dynamic-query filters under active-state visibility, tiered tooltip-panel-modal detail with context preservation), support relate-history-extract through linked highlighting, undo-replay-bookmarks, and selection-query export.
4. Adapt the doctrine to search-first, guided, collaborative, and mobile contexts.
5. Diagnose mantra violations (missing overview, broken continuity, demand flood, recovery gaps) with systematic repairs.
6. Evaluate through task walkthroughs, time-to-insight metrics, and comparative benchmarking across data-product genres.

## Unit 1 — Unit 1

**Scope:** Covers the doctrine's core: the mantra stated and unpacked — the canonical formulation: the overview-first principle (the whole-collection visibility establishing context and patterns before detail — the orientation-before-investigation sequence, the overview's function as cognitive map enabling all subsequent navigation), the zoom-and-filter mechanism (the progressive focus refinement — the zoom for spatial and temporal magnification, the filter for subset selection, the combined dynamics keeping context recoverable during refinement), and the details-on-demand arrival (the specific-item or group information summoned at user request — the tooltip, panel, and drill-down systems as the demand-response layer, the on-demand discipline avoiding premature detail flooding) as the three-beat navigation rhythm; the seven-plus-one tasks — the task taxonomy: the overview task (the collection-scale comprehension — the what-exists-and-how-distributed questions), the zoom task (the item-enlargement for detail), the filter task (the dynamic-query removal of uninteresting items), the details-on-demand task (the single-item and small-group selection), the relate task (the relationship-revelation among items — the connection and correlation discovery), the history task (the undo, replay, and progressive-refinement support — the temporal navigation and interaction-history access), and the extract task (the sub-collection and parameter extraction — the export, selection-reuse, and query-capture needs) with the Plaisant additions (the analyze-and-guide extensions in modern analytics products) as the complete task framework; the eight-golden-tasks interface obligations — the design requirements: the task-to-interface mapping (each information-seeking task demanding specific interface capabilities — the overview requiring summary views, the filter requiring dynamic-query controls, the history requiring undo and state capture), the golden-tasks inventory (the overview, zoom, filter, details-on-demand, relate, history, extract plus the guide-and-collaborate extensions in the analytics-product context), and the task-coverage audit method (the systematic check that a data product's interface serves each task family — the gap-identification discipline) as the requirements-engineering application; the mantra's perceptual foundations — the why-it-works analysis: the cognitive-map support (the overview establishing the mental model that navigation refines — the survey-knowledge construction from the spatial-cognition tradition), the working-memory externalization (the persistent visible context offloading retention burden — the load-theory integration), the preattentive pattern detection (the overview-scale gestalt and salience exploitation — the anomaly and cluster discovery before deliberate search), and the orientation-cost reduction (the zoom-filter continuity preserving positional context — the detail-without-context pitfall prevention) as the scientific grounding; the modern-analytics extensions — the doctrine's evolution: the search-first alternative pattern (the query-and-search entry points complementing browse-first overview navigation — the known-item versus exploratory task split, the search-and-browse integration architectures), the guided-and-recommendation layers (the suggested-insights, anomaly-alerts, and automated-summaries as system-initiated overview — the push-versus-pull information delivery), the collaboration-and-sharing dimensions (the state-capture and view-sharing extending the extract task — the annotation and discussion integration), and the mobile-and-conversational adaptations (the mantra in constrained contexts — the simplified overviews and voice-query interfaces at awareness) as the contemporary practice; the overview-design patterns — the first-beat craft: the summary-visualization families (the KPI-and-scorecard rows, the distribution-overview charts, the map-and-timeline context views, the treemap-and-facets inventory displays), the overview-scale decisions (the whole-collection versus current-segment overview scope, the aggregation-level choices — the overview-honesty with the simplification disclosure), the at-a-glance composition (the single-screen discipline from the Few tradition — the glanceability measurement and layout), and the overview-to-detail bridges (the interactive elements carrying users forward — the clickable-summary and linked-view mechanics) as the overview-craft; the zoom-and-filter design patterns — the second-beat craft: the zoom implementations (the spatial, temporal, and hierarchical zoom mechanics — the semantic-zoom content adaptation across levels, the zoom-continuity preservation of orientation), the filter architectures (the faceted-filter systems — the dimension-based subset controls, the dynamic-query sliders and range selectors, the filter-state visibility and persistence — the active-filter indicator discipline, the clear-all and single-filter-removal ergonomics), the combined zoom-filter flows (the drill-down sequences maintaining recoverable context — the breadcrumb and back-navigation obligations), and the filter-performance realities (the live-filtering response requirements — the sub-100ms feedback connecting to the latency discipline, the progressive-result display under slow queries) as the refinement-craft; the details-on-demand design patterns — the third-beat craft: the detail-display mechanisms (the tooltips for instant micro-detail, the side-panel and drawer patterns for sustained inspection, the modal-and-dedicated-view escalations for deep detail, the inline-expansion within context), the demand-trigger design (the hover, click, select, and keyboard affordances — the discoverability of detail access, the touch-and-accessibility alternatives from the inclusion discipline), the context-preservation requirements (the detail-without-disorientation discipline — the visible connection between detail view and its overview position, the return-path guarantees), and the detail-content curation (the relevant-attribute selection for the item type — the provenance-and-comparison inclusions, the action-affordances within detail contexts) as the demand-craft; the relate-history-extract patterns — the supporting tasks: the relationship-revelation mechanisms (the linked-highlighting across views, the connection-visualization — the network and flow displays, the comparison-and-correlation tools), the history support (the undo-redo for exploration safety, the view-state capture and replay — the session and bookmark systems, the progressive-refinement trails showing the analysis path), and the extraction capabilities (the selection export — the data, image, and view-state downloads, the query-capture — the shareable URLs and saved filters, the report-assembly from collected views) as the supporting-task craft; the mantra-violation diagnostics — the anti-pattern analysis: the missing-overview failures (the detail-first products stranding users — the cold-start disorientation, the dashboard-without-context patterns), the broken-zoom-continuity failures (the drill-downs losing orientation — the context-free-detail pitfall, the filter-state invisibility losing the subset sense), the demand-flood failures (the always-visible detail overwhelming the overview — the everything-important collapse), and the recovery-gap failures (the missing undo, back, and reset paths trapping users in filtered states) with the systematic-repair patterns as the diagnostic-and-fix discipline; the domain-application range — the doctrine's reach: the mantra across data-product genres (the BI dashboards and analytics workbenches, the scientific-exploration tools, the journalism and public-data sites, the operational monitoring systems, the map and spatial products from the spatial discipline, the search-result interfaces) with the genre-adaptation notes (the monitoring-overview versus exploration-overview differences, the narrative-context modifications) as the application breadth; the evaluation-of-mantra-support — the measurement layer: the task-coverage testing (the seven-task walkthrough audits — the can-users-overview-zoom-filter-relate-history-extract verification), the navigation-efficiency metrics (the time-to-insight and orientation-recovery measurements, the lost-user and dead-end detection), and the comparative-benchmark practice (the mantra-support comparison against alternatives and competitors) as the evidence discipline; and the mantra deliverable — the task-framework-fluent navigation doctrine for structuring analytic exploration.
