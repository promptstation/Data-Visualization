# Domain Content Map — Progressive Disclosure and Layered Information Design

Read this during Phase 3 (architecture) and Phase 4 (writing) of the module
development workflow. Verify all factual claims and numbers against the
authoritative sources before publishing (Phase 2 evidence base); flag
anything disputed rather than repeating it.

## Absorbed capabilities this module must produce
1. Design progressive-disclosure systems through the five-depth information-layering model (summary, evidence, detail, context, source) with consistent layer transitions and depth budgets.
2. Select disclosure mechanisms (inline expansion, tooltip-popover-modal overlays, drill-down navigation, progressive forms) via size-frequency-context matrices.
3. Adapt depth by audience expertise, persona defaults, device context, and accessibility parity, engineer trust-layer disclosure (metric definitions, provenance, uncertainty caveats, algorithmic transparency) with meta-signaling affordances.
4. Build chart-specific depth (clean-default toggles, aggregate-to-raw descents, annotation staging, data access) with lazy computation, ensure discoverability through scent engineering, breadcrumbs, deep-link bypasses, and structure overviews verified by findability testing.
5. Diagnose burial-flood-inconsistency-dead-end-illusion failures with repairs, and ground layer decisions in cognitive-load theory through load staging, working-memory protection, and evidence-based depth optimization.
